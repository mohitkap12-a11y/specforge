Tool 1 · Spec Converter

Any spec document to a clean, functional Markdown file.

Kept

  • Heading hierarchy, including Word's automatic section numbers
  • Bullet and numbered lists with nesting
  • Tables, merged cells, tables that continue across pages
  • Code blocks, bold / italic, links, footnotes, image alt text

Dropped

  • Running page headers, footers and page numbers
  • Table-of-contents dot leaders
  • Layout noise such as hyphenated line breaks
  • Markdown-looking text is escaped, so a spec value stays literal

Upload in the web UI (preview, copy, download), call POST /api/convert/markdown, or run specforge to-md spec.pdf. Scanned PDFs need OCR first; legacy .doc needs LibreOffice on the machine.

Tool 2 · Spec Compare

What does the new revision actually change?

01

Pick

Choose a spec and two versions from the library in drop-downs.

02

Match

Sections and tables are matched by title, so renumbering is not mistaken for new content.

03

Diff

Sentence-level and table-row changes, with the exact words that moved.

04

Rank

Breaking, new, changed, clarification, editorial: a shall weakened to should is breaking.

05

Summarise

Optional AI summary of what the version brings, citing only detected changes.

Code finds and classifies every change; AI only describes them, and the full change list stays the authoritative record. Export the comparison as a Markdown report, or run specforge compare nvme-base 2.3 2.4.

Tool 3 · Coverage Tool · the problem

Coverage of a 1,000-page standard is judged by hand today.

Without SpecForge

  • Coverage is a spreadsheet maintained manually
  • Spec revisions change; nobody knows what moved
  • “Are we covered?” is an opinion, not a measurement
  • Gaps are found late, in the field

With SpecForge

  • The denominator is generated from the spec itself
  • New revision? Reparse and diff, nothing silently lost
  • Every verdict links to the exact commands that prove it
  • Gaps are visible, ranked, and exportable today

All three tools · the design rule

Code decides. AI only drafts.

A coverage number or a change list you cannot reproduce is worthless. Changes, scenarios and verdicts come from deterministic code. AI only describes: it summarises a version comparison, describes executed flows, proposes the requirements they exercise and suggests scenarios for gaps; nothing it writes counts until a person approves it.

Code (deterministic)

What exists
What is covered
Every verdict

AI (assistive)

Describes executed flows
Proposes requirement links
Never scores

AI output is schema-validated, limited to requirements it was shown, and has zero effect on coverage until approved.
